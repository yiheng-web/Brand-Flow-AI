# Brand-Flow 原型设计 / UI 设计需求文档

> 文档版本：v1.0  
> 适用对象：产品经理、原型设计同学、UI 设计同学、前端研发、后端研发、AI 逻辑研发、测试同学  
> 文档目的：基于 Brand-Flow 当前已确定的产品需求，定义系统页面结构、核心业务流程、模块交互逻辑、版本拆分、页面原型要求和研发实现边界，使设计与研发可以按本文档完成后续原型设计与开发拆解。

---

## 1. 产品总定位

Brand-Flow 是面向个人创作者、团队和企业的 AI 图文创作平台。

产品核心能力：

```text
用户输入自然语言需求
↓
系统调用个人 / 团队 / 企业知识库
↓
AI 将创作过程拆成透明节点
↓
用户在关键节点确认、选择、修改
↓
系统生成候选底图
↓
根据需求决定是否进行图文合成
↓
AI 进行品牌质检与质量评估
↓
用户保存、导出、复用作品
```

产品差异点：

| 差异点 | 说明 |
|---|---|
| 白盒化节点流 | 不是黑盒生图，而是把 AI 创作过程拆成可解释节点 |
| 多层知识库 | 支持个人、团队、企业知识库参与创作 |
| Space 创作空间 | 每次创作绑定个人、团队或企业空间 |
| 图文分离 | 底图生成与文字/Logo 合成分离，避免 AI 中文乱码 |
| 品牌质检 | AI 根据需求、品牌规则、画面和排版进行评分 |
| 作品沉淀 | 每次创作都保存为作品，可再次编辑和复用 |

## 2. 版本规划

### 2.1 V1.0：最小可上线版本

目标：完成从注册登录到生成、质检、保存、导出的完整闭环。

V1.0 必须包含：

```text
1. 登录注册
2. 首页创作入口
3. Space 选择
4. 知识库选择
5. 7 节点创作流
6. 知识库基础管理
7. 素材上传与管理
8. 作品中心
9. 作品详情
10. 基础导出
11. 用户个人中心
```

V1.0 不包含：

```text
用户自定义模型
复杂局部重绘
PS 级图层系统
多人实时协同编辑
复杂审批流
公开素材市场
自动解析 PDF 品牌规范
多级部门嵌套
```

### 2.2 V1.1：团队协作增强版本

目标：让团队可以共享知识库、管理成员、复用团队作品。

V1.1 增加：

```text
1. 团队创建与管理
2. 团队成员邀请
3. 团队角色管理
4. 团队知识库审核
5. 团队作品中心
6. 版本记录
7. 站内通知
```

### 2.3 V1.2：企业管理版本

目标：支持企业级品牌资产管控和团队管理。

V1.2 增加：

```text
1. 企业创建与管理
2. 企业知识库
3. 企业品牌规则
4. 企业成员管理
5. 企业下团队管理
6. 企业强制知识库
7. 企业导出权限
8. 企业额度统计
```

### 2.4 V2.0：商业化与高级能力版本

目标：支持计费、额度、安全、模板、多尺寸和高级编辑。

V2.0 增加：

```text
1. 额度与套餐
2. 水印策略
3. 内容安全检测
4. 多尺寸导出
5. 模板中心
6. Bad Case 反馈
7. 操作日志
8. 管理后台
```

## 5. 登录注册模块

### 5.1 页面目标

用户完成账号注册、登录和退出，为后续 Space、知识库、作品归属提供身份基础。

### 5.2 页面清单

| 页面 | 路由 | 说明 |
|---|---|---|
| 登录页 | /login | 邮箱密码登录 |
| 注册页 | /register | 邮箱密码注册 |
| 个人中心 | /profile | 用户信息和退出登录 |

### 5.3 登录页 UI 要求

登录页包含：

```text
产品 Logo
产品 slogan
邮箱输入框
密码输入框
登录按钮
跳转注册入口
错误提示区域
```

登录成功后进入首页。

登录失败时展示错误提示：

```text
邮箱或密码错误，请重新输入。
```

Token 过期时跳转登录页并提示：

```text
登录状态已过期，请重新登录。
```

### 5.4 注册页 UI 要求

注册页包含：

```text
昵称输入框
邮箱输入框
密码输入框
确认密码输入框
注册按钮
跳转登录入口
```

注册成功后跳转登录页或自动登录进入首页。V1.0 执行自动登录。

### 5.5 研发实现要求

前端必须保存：

```ts
interface AuthState {
  token: string;
  user: {
    id: string;
    nickname: string;
    email: string;
    avatar?: string;
  };
}
```

所有业务接口必须携带 Authorization Header。

## 6. Space 创作空间模块

### 6.1 模块目标

Space 是用户当前创作上下文。Space 决定知识库范围、素材范围、作品归属、权限策略、企业规则和额度归属。

### 6.2 Space 类型

```ts
type SpaceType = 'personal' | 'team' | 'enterprise';
```

| Space 类型 | 说明 | 作品归属 |
|---|---|---|
| personal | 个人空间 | 当前用户 |
| team | 团队空间 | 当前团队 |
| enterprise | 企业空间 | 当前企业 |

### 6.3 Space 切换器

Space 切换器位于顶部栏。

展示格式：

```text
当前空间：个人空间 v
```

下拉内容：

```text
个人空间
团队空间 A
团队空间 B
企业空间 A
```

切换 Space 后，系统必须刷新：

```text
首页默认知识库
知识库列表
素材列表
作品中心列表
团队/企业权限
导出权限
```

### 6.4 业务规则

1. 用户默认拥有个人空间。
2. 用户加入团队后出现团队空间。
3. 用户加入企业后出现企业空间。
4. 用户在团队空间创作的作品归属团队。
5. 用户在企业空间创作的作品归属企业。
6. 企业强制规则只在企业空间和所属团队空间中生效。

## 7. 首页创作入口模块

### 7.1 页面目标

首页是用户发起创作任务的入口。用户必须在首页完成 Space 确认、知识库选择和自然语言需求输入。

### 7.2 页面布局

首页主区域结构：

```text
页面标题：今天想创作什么？
Space 信息卡片
知识库选择区
创作需求输入框
生成模式提示区
开始创作按钮
最近作品区域
```

### 7.3 Space 信息卡片

展示当前 Space：

```text
当前空间：个人空间
作品将保存到：我的作品
可用知识库：3 个
```

团队空间示例：

```text
当前空间：瑞幸新品项目组
作品将保存到：团队作品
企业品牌规则：已启用
```

### 7.4 知识库选择区

用户在首页必须先确认 Space，再选择知识库。

知识库选择规则：

| Space 类型 | 可选知识库 | 默认选择 |
|---|---|---|
| personal | 个人知识库 | 最近使用的个人知识库 |
| team | 团队知识库 + 企业强制知识库 + 企业允许的个人知识库 | 团队主知识库 |
| enterprise | 企业知识库 | 企业主知识库 |

一次最多选择 3 个知识库。

企业强制知识库自动选中且不可取消。

无知识库时展示：

```text
当前未选择知识库，本次创作将不使用知识库素材和规则。
```

### 7.5 创作需求输入框

输入框支持自然语言。

占位文案：

```text
例如：帮我做一张夏日冰咖啡新品海报，清爽年轻，适合小红书发布，标题写“夏日第一杯清爽咖啡”。
```

输入为空时，开始创作按钮禁用。

### 7.6 开始创作按钮

点击后系统创建 workflow，并跳转节点流工作台。

请求必须包含：

```ts
interface CreateWorkflowRequest {
  spaceId: string;
  spaceType: SpaceType;
  selectedKnowledgeBaseIds: string[];
  originalPrompt: string;
}
```

## 8. 节点流工作台模块

### 8.1 页面目标

节点流工作台负责展示完整白盒化创作流程。用户在该页面查看每个节点的中间产物、修改关键字段、选择方案、确认生成、查看质检结果和保存作品。

### 8.2 页面布局

节点流页面必须采用三栏布局：

```text
┌────────────┬────────────────────┬────────────────────┐
│ 左侧节点流  │ 中间节点详情        │ 右侧实时预览        │
└────────────┴────────────────────┴────────────────────┘
```

### 8.3 左侧节点流导航

左侧固定展示 7 个节点：

```text
1. 需求翻译
2. 品牌约束
3. 创意方案
4. Prompt 生成
5. 底图生成
6. 图文合成
7. 品牌质检
```

节点状态：

```text
pending
running
completed
failed
stale
skipped
```

每个节点必须展示：

```text
节点名称
节点状态
是否被用户修改
是否已失效
失败原因或跳过原因
```

## 9. 节点一：需求翻译 UI 设计

### 9.1 页面目标

将用户输入翻译成结构化 Creative Brief，并让用户确认系统是否理解正确。

### 9.2 中间详情区

使用固定卡片结构展示：

```text
作品类型
输出模式
文字处理方式
目标平台
画面比例
目标受众
核心主体
场景环境
情绪基调
视觉风格
色彩倾向
文案需求
必须包含
必须避免
```

字段结构固定，字段内容由 AI 生成。

### 9.3 输出模式卡片

输出模式固定为：

```text
纯图片
图文成片
```

业务逻辑：

| 输出模式 | needsComposition | 后续逻辑 |
|---|---|---|
| 纯图片 | false | 图文合成节点 skipped |
| 图文成片 | true | 图文合成节点 pending |

### 9.4 文字处理方式卡片

可选项固定为：

```text
纯图片，不添加文字
画面中自然出现文字
后期叠加标题/Logo/文案
两者都有
```

业务定义：

| 类型 | 说明 |
|---|---|
| none | 不出现任何用户指定文字 |
| scene_text | 文字是画面场景的一部分，如招牌、路牌 |
| overlay_text | 文字是后期叠加的标题、Logo、文案 |
| both | 同时包含场景文字和后期叠加文字 |

### 9.5 用户操作

用户必须能：

```text
修改字段值
新增标签
删除标签
修改标题/副标题/CTA
切换输出模式
切换文字处理方式
确认进入下一节点
```

### 9.6 右侧预览区

右侧展示 Brief 摘要，不展示图片。

## 10. 节点二：品牌约束 UI 设计

### 10.1 页面目标

从用户选择的知识库中匹配素材、规则、Prompt 模板和禁用项，并形成 BrandConstraintPackage。

### 10.2 条件运行

满足以下任一条件时运行：

```text
用户选择了知识库
当前 Space 有企业强制知识库
当前 Space 有强制品牌规则
```

否则节点状态为 skipped。

### 10.3 中间详情区

必须分为三组：

```text
强制使用项
推荐使用项
可选参考项
```

每个卡片展示：

```text
缩略图 / 类型图标
标题
所属知识库
类型
匹配分数
推荐理由
是否已选择
```

### 10.4 强制使用项

强制使用项不可取消。

前端展示锁定标识：

```text
企业强制规则，无法取消
```

### 10.5 用户操作

用户必须能：

```text
查看匹配结果
查看推荐理由
勾选推荐项
勾选可选项
查看强制项
确认进入创意方案节点
```

### 10.6 右侧预览区

右侧展示已选择素材的集合预览。

## 11. 节点三：创意方案 UI 设计

### 11.1 页面目标

生成 3 个差异明确的创作方向，让用户先选择创意方向，再进入 Prompt 生成。

### 11.2 中间详情区

展示 3 张创意方案卡片。

每张卡片包含：

```text
方案标题
方案摘要
视觉风格
构图方式
色彩倾向
场景描述
适用平台
推荐理由
风险提示
选择按钮
```

### 11.3 方案规则

系统必须生成 3 个方案。  
用户必须选择 1 个方案。  
当前版本不支持合并多个方案。

### 11.4 用户操作

用户必须能：

```text
选择方案
重新生成方案
补充方向要求
确认进入 Prompt 生成节点
```

### 11.5 右侧预览区

展示当前选中方案的概要和后续生成倾向。

## 12. 节点四：Prompt 生成 UI 设计

### 12.1 页面目标

将 Creative Brief、BrandConstraintPackage 和选中的创意方案转化为结构化 PromptPlan。

### 12.2 中间详情区

展示模块固定为：

```text
主体描述
场景背景
风格方向
构图方式
光影效果
品牌约束
文字安全区域
Negative Prompt
排版计划
生成模式
```

### 12.3 分支逻辑

当 `needsComposition = true`：

```text
layoutPlan 必须存在
必须展示文字安全区域
必须提示：底图不直接生成最终中文标题
```

当 `needsComposition = false`：

```text
layoutPlan = null
隐藏文字安全区域编辑
展示：当前任务为纯图片生成，不执行图文合成
```

### 12.4 生成模式

前端展示：

```text
真实摄影
商业海报
插画风格
快速草稿
高质量精修
```

后端映射具体模型和参数。

### 12.5 用户操作

用户必须能：

```text
修改 Image Prompt
修改 Negative Prompt
修改文字安全区
修改生成模式
恢复 AI 推荐版本
确认进入底图生成节点
```

### 12.6 右侧预览区

展示 Prompt 摘要、选中知识库素材摘要、生成模式。

## 14. 节点六：图文合成 UI 设计

### 14.1 页面目标

根据需求决定是否执行图文合成。需要图文成片时，系统使用模板和图层叠加标题、Logo、文案；纯图片任务跳过该节点。

### 14.2 状态一：启用

当 `needsComposition = true` 时，图文合成节点启用。

页面展示：

```text
图文合成节点
状态：已启用
原因：当前任务需要叠加标题、Logo 或营销文案
```

编辑器包含：

```text
画布预览
模板选择
图层列表
属性面板
导出按钮
保存作品按钮
```

## 30. 最终验收标准

原型/UI 文档对应功能完成后，必须满足：

1. 用户可以从首页完整发起一次创作；
2. 用户可以选择 Space 和知识库；
3. 用户可以完成 7 节点创作流程；
4. 纯图片任务会跳过图文合成节点；
5. 图文成片任务会进入图文合成节点；
6. 用户可以查看每个节点的中间产物；
7. 用户可以修改关键节点字段；
8. 用户可以生成 4 张候选底图；
9. 用户可以查看候选图评分；
10. 用户可以完成图文合成；
11. 用户可以查看最终质检报告；
12. 用户可以保存作品；
13. 用户可以在作品中心找回作品；
14. 用户可以导出图片；
15. 权限不足时前端隐藏操作且后端拒绝操作；
16. 所有关键空状态和错误状态都有明确提示。

## 31. 总结

Brand-Flow 的原型和 UI 设计必须围绕一条主线展开：

```text
创作入口
↓
白盒节点流
↓
知识库与素材支撑
↓
图文合成或纯图片输出
↓
品牌质检
↓
作品沉淀
```

V1.0 的目标是完成可上线闭环。  
V1.1 的目标是补齐团队协作。  
V1.2 的目标是补齐企业管控。  
V2.0 的目标是补齐商业化和高级创作能力。

设计和研发必须优先保证主流程完整，其次再增强局部体验。
