# Brand-Flow AI Web UI/UX 审计报告

> 审计日期：2026-07-16  
> 审计范围：`apps/web/src`、根目录业务与编码文档、现有 Ant Design / React Flow / Fabric.js 使用情况  
> 原则：不修改 API 契约、不重构 Zustand 数据结构、不以静态假数据替代真实业务数据。

## 1. 当前页面与核心业务流程

### 页面与路由

| 页面              | 当前路由              | 当前状态             | 主要职责                               |
| ----------------- | --------------------- | -------------------- | -------------------------------------- |
| 登录 / 注册       | `/login`、`/register` | 已接入认证 API       | 用户认证与表单校验                     |
| 首页              | `/home`               | 可用，但偏单一输入页 | Space 切换、创意输入、创建 Workflow    |
| 工作台            | `/workspace`          | 核心链路可用         | SSE 执行、节点查看/修改/重跑、结果预览 |
| 品牌档案          | `/brand`              | 占位                 | 当前仅分类导航，无真实内容             |
| 个人中心          | `/profile`            | 可用                 | 个人信息、企业/团队与退出              |
| 知识库列表 / 详情 | 组件已存在，路由缺失  | 不可从应用访问       | 知识库和知识项 CRUD、文本向量化        |

文档规划中还包含素材、作品中心、作品详情和导出，但前端路由与页面尚未完整落地。`BasicLayout.tsx` 已不在当前路由树中，属于遗留实现。

### 当前核心流程

1. 用户登录后进入首页并选择个人、团队或企业 Space。
2. 用户输入创意，首页调用 `submitPrompt` 创建工作流并进入 `/workspace`。
3. Workspace 通过 SSE 接收节点开始、完成、跳过、失败与工作流完成事件。
4. 用户在 React Flow 画布中选择节点，在右侧面板查看输出、调整部分参数或从指定节点重跑。
5. 图像生成完成后可进入预览并下载图片；作品保存、版本历史和正式导出尚未形成完整前端闭环。

当前前端展示 6 个节点：意图解析、知识匹配、Prompt、图像生成、排版合成、自我评估；业务文档冻结的 V1 流程为 7 个节点，并新增“创意方案”。后端事件名称与前端展示名称也存在过渡映射。

## 2. 现有设计问题

- 应用缺少统一产品壳层：首页自行实现 Logo 与顶部栏，Workspace 又有独立顶部栏，页面间导航与全局操作不稳定。
- Workspace 更接近“画布 + 属性栏”，缺少节点库、资源入口、自动保存、运行主操作和用户可读的执行摘要。
- 页面层级主要靠边框、阴影和随机浅色区分，缺少一致的 Surface 层级。
- 主操作权重不稳定：首页“开始创作”明确，但 Workspace 没有稳定的运行/重跑主操作；导出、保存、预览分散。
- 空、错、加载状态由纯文本、Spin、Empty 和局部 message 混用，缺少一致的状态组件与重试路径。

## 3. 信息架构问题

- 主导航仅有首页、工作台、品牌档案，知识库组件虽已实现却未注册路由，素材与作品中心也没有完整入口。
- “品牌档案”“知识库”“素材资产”的业务边界不清，品牌页分类与文档规划的独立知识库/素材模块重复。
- 首页只承载创意输入，没有“最近项目 / 最近生成 / 模板 / 品牌资产”等继续工作的入口。
- Workspace 的节点选择、视图切换、执行状态和结果预览集中在一条轻量顶栏中，缺少任务级与节点级信息分层。
- 详细日志、版本历史、执行费用和队列信息没有用户可理解的承载位置。

## 4. 视觉一致性问题

- `index.css`、各 CSS Module 与 JSX 内同时存在大量十六进制色值、RGBA、阴影和圆角；同一主色出现 `#2f6cf6`、`#4f6ff7`、`#1677ff` 等多套值。
- 未在入口使用 Ant Design `ConfigProvider`，Ant Design 组件与自定义组件没有共享 Token。
- 圆角从 4px 到 28px、阴影从轻卡片到高饱和蓝色发光并存，缺少层级规则。
- 字号、字重、间距缺少系统化命名；Workspace 单个 CSS Module 超过 1700 行，重复视觉规则较多。
- FlowNode 使用 Emoji 作为正式节点图标，并在 JSX 内写颜色、阴影；画布按钮同样使用内联样式。

## 5. 交互问题

- React Flow 所有默认边均永久动画，不符合执行路径语义，也产生不必要的视觉噪音。
- 节点只有 done/running/pending/failed 四态，无法表达未配置、就绪、排队、警告和跳过；状态点主要依赖颜色。
- 画布的布局切换、MiniMap 开关与 React Flow Controls 分散，纯图标/符号缺少完整 Tooltip、`aria-label` 与一致焦点反馈。
- 右侧面板无关闭/折叠能力，节点未选择时只显示“请选择一个节点”，没有引导或节点摘要。
- 首页“退出”按钮没有绑定动作；“切换 Space”派发自定义事件，但 SpaceDropdown 未监听该事件。
- 知识库详情仍频繁使用 Modal 编辑，部分图标操作缺少可读标签或 Tooltip。
- 工作台下载是浏览器直链下载，尚未接入作品保存、版本和正式导出流程。

## 6. 响应式问题

- AppLayout 侧栏宽度固定，未根据 1024px 自动折叠，也缺少窄屏提示。
- Workspace 使用固定右侧面板与全高画布，没有面板抽屉化、最小画布宽度或窄屏降级策略。
- 首页仅在 640px 做局部适配，1024/1280/1440 三档缺少明确布局规则。
- 多个页面使用 `100vw/100vh` 与内部固定高度组合，容易在浏览器缩放、系统缩放或移动视口产生溢出。

## 7. 可访问性问题

- 多个纯图标按钮只使用 `title` 或没有辅助名称，未统一提供 Tooltip 与 `aria-label`。
- 自制下拉选项使用可点击 `div`，不支持键盘方向键、Enter 或标准 Listbox 语义。
- 状态主要依赖圆点颜色，缺少图标、文本和辅助说明的冗余表达。
- 全局未定义统一 `:focus-visible`，部分按钮通过 `border: none` 移除了可见焦点。
- 灯箱使用普通 `div` 模拟对话框，没有 `role="dialog"`、焦点管理和 Escape 关闭。
- 未全局处理 `prefers-reduced-motion`，且执行边持续动画。

## 8. 技术债

- `useWorkflowStore` 的流数据使用 `Record<string, any>`；Workspace 的 SSE 处理也有多处 `any`，事件契约缺少判别联合类型。
- 6 节点前端模型与 7 节点 V1 文档不一致；`stale` 被映射为 done，`skipped` 也被展示为 done，丢失真实语义。
- Workspace 同一文件同时负责 SSE、状态恢复、业务数据适配、下载、节点编辑和完整页面渲染，职责过重。
- `workspace.module.css` 体积过大且包含多组面板私有样式，复用边界不清。
- 全局 React Flow 内部类覆盖使用 `!important`，与组件级样式和未来版本升级耦合。
- 知识库页面存在 `catch (err: any)`、内联样式和 TODO 操作；路由与导航未挂载。
- Fabric.js 依赖已安装，但当前已审查页面中未发现稳定的精修画布实现，不能将“画板”视为已完成精修功能。

## 9. 风险较高的修改区域

| 区域                     | 风险                                           | 控制策略                                                         |
| ------------------------ | ---------------------------------------------- | ---------------------------------------------------------------- |
| Workspace SSE 与状态恢复 | 高：影响长任务、断线重连和节点重跑             | 保留 API 与 Store 写入方式，先拆展示层，不改事件 URL 与请求契约  |
| 6 → 7 节点迁移           | 高：后端 Schema / Agent Graph 仍可能处于过渡期 | 前端状态模型先支持完整语义，真实新增节点需与后端事件映射同步上线 |
| 节点输出面板             | 高：依赖 Agent 输出形态                        | 保留现有适配函数，逐节点迁移并提供未知字段兜底                   |
| 图像预览 / 下载          | 中：跨域图片可能导致 fetch 失败                | 保留原行为，后续接入 works/export API 时替换                     |
| 全局主题                 | 中：可能影响所有 Ant Design 组件               | 使用语义 Token 和有限的 component token，避免全局裸标签覆盖      |
| AppLayout 与路由         | 中：影响所有受保护页面                         | 保留 URL 和 AuthGuard，先统一壳层再补已存在页面路由              |
| Fabric 精修区            | 高：当前实现基础不足                           | 本轮不伪造精修能力，待画布数据与保存契约明确后单独实施           |

## 10. 推荐重构优先级

### P0：基础一致性与核心链路

1. 建立设计 Token、Ant Design Theme、全局焦点与 reduced-motion 规则。
2. 提供 AppShell、PageHeader、StatusBadge、Empty/Loading/ErrorState、IconButton 等稳定组件。
3. 重构 Workspace 顶栏、画布工具栏、节点卡、检查器和底部执行状态区。
4. 仅对正在运行的边启用动画；状态同时使用图标、文本与颜色。
5. 修复首页退出、Space 选择和 Workspace 硬编码 `spaceId` 等直接影响操作闭环的问题。

### P1：高频页面与信息架构

1. 将已存在的知识库列表/详情注册到路由与主导航。
2. 将品牌档案逐步收敛为品牌资产入口，避免与知识库、素材库重复。
3. 首页增加继续工作导向的最近项目、模板和最近生成区；数据不存在时使用真实空状态，不伪造业务记录。
4. 统一登录、注册、个人中心、知识库的 PageHeader、表单与异步状态。

### P2：完整创作闭环

1. 与后端同步 7 节点、stale/skipped/queued/warning 状态与事件 Schema。
2. 接入作品保存、作品中心、详情、版本与正式导出。
3. 在明确 Fabric 画布数据和保存契约后实现局部精修。
4. 增加关键交互测试、axe 可访问性检查与截图回归。
